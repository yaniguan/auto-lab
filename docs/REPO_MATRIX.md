## `L6` · [lab-ask-why](https://github.com/yaniguan/lab-ask-why)

- **Tagline**: Socratic co-scientist that surfaces supporting and contradicting rationale sentences, hidden assumptions, and mind-changing experiments instead of picking a winner
- **Object**: Epistemic disagreement and rationale-probing module (`L6`) for the Auto-Lab brain: rather than collapsing scientific uncertainty into a binary verdict, it retrieves verbatim evidence sentences on each side of a claim, surfaces necessary assumptions, and frames the discriminating experimental result that would resolve the disagreement.
- **Data**: Evaluates on the SciFact dev split (Wadden et al., EMNLP 2020; CC BY-NC 2.0, fetched on demand to gitignored `data/` with zero redistribution): 5,183 corpus abstracts (mean 9.7, median 8 sentences) and 300 dev claims, where 188 evidence-bearing claims yield 209 `(claim, doc_id)` pairs (138 `SUPPORT`, 71 `CONTRADICT`; 112 `NOINFO` claims excluded). Also curates SciRIFF, LAB-Bench, 9 co-scientist/debate repositories, and 13 papers (2018-2026).
- **Model**: Zero-parameter Okapi BM25 lexical sentence ranker (`k1 = 1.2`, `b = 0.75`) over lowercased `[a-z0-9]+` tokens (29 stopwords removed) using corpus-wide sentence IDF and average sentence length (`avgdl`), benchmarked against a 20-seed uniform random permutation baseline and paired with a deterministic 3-question epistemic probe generator (`why_questions`).
- **Training**: Zero parametric training or LLM API calls (`numpy` + Python standard library on CPU in < 1s). Achieves 0.493 Hit@1 (`recall@1`) and 0.789 Hit@3 (`recall@3`) on 209 SciFact dev claim-abstract pairs vs. 0.197 +- 0.024 and 0.528 +- 0.029 for 20-seed random ranking, with near-symmetric performance on `SUPPORT` (0.507 / 0.797) and `CONTRADICT` (0.465 / 0.775).
- **History**: Initialized in `6236123` (2026-11-18) with `demo/why_probe.py`, reference capture `demo/output.txt`, Python 3.12 GitHub Actions workflow (`.github/workflows/demo.yml`), and curated scientific debate/RAG catalog; architecture and ecosystem profile documented in `bbef3b6`.
- **Unique Properties**:
  - Stance-neutral Socratic design that retrieves both `SUPPORT` (0.797 top-3) and `CONTRADICT` (0.775 top-3) rationales with near-equal fidelity instead of forcing premature verdict collapse
  - Fast, deterministic, zero-API-cost CPU attribution baseline (`numpy` only) establishing an interpretable lexical floor before neural reranking or multi-agent debate
  - Strict non-commercial (`CC BY-NC 2.0`) data isolation via on-demand gitignored `data/` retrieval while keeping repository code MIT-licensed
  - Complements `lab-decide` at Layer `L6` by pairing hypothesis-discriminating test generation with conformal applicability-domain gating
- **Deep Profile**: [`lab-ask-why/docs/ARCHITECTURE_AND_HISTORY.md`](https://github.com/yaniguan/lab-ask-why/blob/main/docs/ARCHITECTURE_AND_HISTORY.md)

## `L6` · [lab-decide](https://github.com/yaniguan/lab-decide)

- **Tagline**: Uncertainty-aware experiment advisor combining split conformal prediction intervals, kNN trust-region abstention, and active boundary expansion
- **Object**: Epistemic decision and applicability-domain layer (`L6`) under the Auto-Lab brain: delivers distribution-free calibrated prediction intervals inside its trusted chemical/experimental manifold, emits explicit 'I don't know' abstentions outside it, and recalibrates as new laboratory measurements expand the boundary.
- **Data**: Evaluates on ESOL aqueous solubility (`delaney-processed.csv`, Delaney 2004; 1,128 organic compounds fetched on demand to gitignored `data/`, split 676 train / 226 calibration / 226 test at `SEED = 0`) using 6 physical/topological descriptors while excluding the CSV's pre-fitted `ESOL predicted` column. Also curates 5 reaction/experiment optimization benchmarks (`ESOL`, `EDBO`, `EDBO+`, `rxn_yields`, `Olympus`), 12 BO & conformal libraries (`BoTorch`, `Ax`, `MAPIE`, `BayBE`, `TuRBO`, `SafeOpt`), and 12 papers (2012-2026).
- **Model**: Scikit-learn `GradientBoostingRegressor(random_state=0)` paired with finite-sample Split Conformal Prediction (`alpha = 0.10`, quantile level `min(1, ceil((n_cal+1)*(1-alpha))/n_cal)` with `method='higher'`) and a standardized 6D Euclidean `NearestNeighbors(n_neighbors=5)` applicability-domain gate (`StandardScaler` + 80th-percentile calibration distance threshold `thr = 0.758`).
- **Training**: CPU-only surrogate fitting, split conformal calibration, and 3-round simulated boundary acquisition (< 1s on CPU; `numpy`, `pandas`, `scikit-learn`). Achieves 0.912 marginal test coverage (`q = 1.522` log units, width `3.044`, MAE `0.704`), stratifying into `0.656` MAE / `0.922` coverage inside the trust region (`n = 180`, 79.6% answered) vs. `0.892` MAE / `0.870` coverage outside (`n = 46`, 20.4% abstained). Locally adaptive intervals (CQR), separate pool/test splits, and `BoTorch` loops remain roadmapped.
- **History**: Initialized in `41dae77` (2026-11-18) with `demo/conformal_trust.py`, reference capture `demo/output.txt`, Python 3.12 GitHub Actions workflow (`.github/workflows/demo.yml`), and curated Bayesian optimization & conformal prediction catalog; architecture and ecosystem profile documented in `6b03cfc`.
- **Unique Properties**:
  - Decouples distribution-free finite-sample interval calibration (`q = 1.522`) from kNN applicability-domain abstention (`d_5NN <= 0.758`), isolating low-error in-domain answers (`MAE 0.656`) from OOD queries (`MAE 0.892`)
  - Excludes Delaney's pre-fitted `ESOL predicted` column to prevent target leakage into descriptor-based surrogate calibration
  - Explicitly documents pool-shrinking survivor bias (`180 -> 176` answered test points across active boundary rounds) rather than overclaiming OOD generalization
  - Pairs with `lab-ask-why` (`L6`), `labbench-posttrain` (`L3`), and `lab-rehearsal`/`lab-verify` (`L4`) to gate closed-loop wet-lab experiment proposals
- **Deep Profile**: [`lab-decide/docs/ARCHITECTURE_AND_HISTORY.md`](https://github.com/yaniguan/lab-decide/blob/main/docs/ARCHITECTURE_AND_HISTORY.md)

## `L5` · [buy-or-make](https://github.com/yaniguan/buy-or-make)

- **Tagline**: Cost-aware chemical vendor availability and N-step retrosynthetic reachability triage with conservative listed-price lower bounds, strict null/unknown honesty, and assayfold-aligned schemas.
- **Object**: Verifies whether candidate molecules proposed by L6/L5 scientific planners (lab-ask-why, lab-decide) are directly purchasable from chemical vendors or makeable in N steps from purchasable building blocks, computing conservative leaf-only stoichiometric cost lower bounds strictly from real listed catalog prices while keeping missing prices null and unverified molecules unknown.
- **Data**: Twelve license-audited external data and model sources in buyormake/sources.py (PubChem PUG-REST/PUG-View, ZINC, Enamine, eMolecules, Mcule, AiZynthFinder models & ZINC stock, USPTO Lowe CC0-1.0, Open Reaction Database CC-BY-SA-4.0, RDKit SA_Score, Coley SCScore, RAscore; non-redistributable caches/catalogs isolated in gitignored data/), 5 Pydantic v2 / JSON Schema contracts (extra='forbid', schema/), and a 20-molecule CPU benchmark (examples/demo.py, examples/demo_output.md).
- **Model**: RDKit canonical isomeric SMILES and InChIKey normalization, multi-format LocalStockBackend (.tsv, .csv, .jsonl, .smi, .sqlite, .hdf5) + rate-limited SQLite-cached PubChemVendorBackend, 3-tier retrosynthesis search (optional AiZynthFinder MCTS, local USPTO/ORD SQLite product lookup, and a 14-template RDKit SMARTS 2-step disconnection engine), mass-normalized USD/g stoichiometric leaf cost estimator, and SAscore + pure-NumPy 5-layer Morgan-FP SCScore inference.
- **Training**: Zero in-repository model training; combines deterministic RDKit cheminformatics, live/local catalog lookup, and stoichiometric cost algebra with RDKit's fragment-based SAscore heuristic and frozen pretrained Reaxys SCScore weights (6.18 MB NumPy JSON.gz, optional CC-BY-4.0 AiZynthFinder USPTO ONNX policy networks).
- **History**: Initial release 76991c8 on main (2026-11-18: buyormake package, 5 JSON Schemas, 8 fetch scripts, 20-molecule CPU demo, 7 pytest modules, Python 3.10-3.12 CI), open review branch origin/review-fixes (bbfa649, 2026-11-18: buyable cost_complete=False fix, mixed-currency/pack-size non-comparability, excluded-leaf reporting in est_cost_method, indirect ZINC license check marker, and 2-layer SCScore test), and conflict-free architecture documentation ff8e530 on main.
- **Unique Properties**:
  - Strict epistemic honesty on prices and reachability: never fabricates missing catalog prices (price=null, price_basis='unknown') and never conflates bounded search failure ('unknown') with synthetic impossibility.
  - Completeness-tracked leaf-only route cost lower bounds (sum of cheapest USD/g * count * MW_leaf / MW_target per 1 g target) distinguishing complete leaf coverage from partial lower bounds.
  - Zero-redistribution license gate recording explicit commercial_use_ok, redistribution_ok, and license_quote metadata across 12 sources while keeping fetched vendor data gitignored.
  - Timestamp-invariant SHA-256 sealed AvailabilityRecord contracts sharing Source, Quantity, Uncertainty, Provenance, and Molecule types with assayfold (L0).
- **Deep Profile**: [`buy-or-make/docs/ARCHITECTURE_AND_HISTORY.md`](https://github.com/yaniguan/buy-or-make/blob/main/docs/ARCHITECTURE_AND_HISTORY.md)

## `L5` · [labshift](https://github.com/yaniguan/labshift)

- **Tagline**: Synthetic multi-instrument lab scheduling benchmark, sweep-line verifier, greedy baseline, and OR-Tools CP-SAT solver with coupled min/max wait windows.
- **Object**: Models and solves executive multi-job laboratory scheduling across shared finite-capacity instrument pools (liquid_handler, incubator, plate_reader, centrifuge, washer) under integer-minute operation chains, job release times, hard deadlines, minimum equilibration waits (min_wait), and upper perishability windows (max_wait).
- **Data**: Frozen JSON-serializable dataclasses (Instance, Job, Operation, Schedule, ScheduledOp), a seeded workflow generator spanning 6 liquid-handling assay templates (3..6 ops/job across small [6 jobs], medium [12 jobs], and large [20 jobs] presets), and a committed 30-instance MIT-licensed benchmark suite in benchmarks/ (seeds 1000..1009, 1100..1109, 1200..1209).
- **Model**: Three-stage independent schedule verifier (completeness/duration bijection, intra-job release/precedence/min_wait/max_wait/deadline checks, and departure-first (t, -1) interval sweep-line capacity checking), a myopic (ready_time, deadline, duration, job_id) priority list-scheduling baseline (labshift.greedy), and an OR-Tools CP-SAT IntervalVar + no_overlap/cumulative makespan minimizer exporting dual best_objective_bound optimality gaps (labshift.cpsat).
- **Training**: Contains no internal neural weights; provides a deterministic combinatorial optimization benchmark, exact millisecond feasibility/reward verifier (check_schedule + compute_metrics), and CP-SAT optimal/near-optimal trajectory teacher for RLVR and LLM planning evaluation. All 30 benchmark instances were evaluated on CPU (2026-11-18, 5s CP-SAT limit).
- **History**: Initial release 124a6d7 on main (2026-11-18: models, seeded generator, 30 committed benchmark JSONs, sweep-line checker, greedy & CP-SAT solvers, metrics, ASCII Gantt renderer, CLI, 4 test modules, Python 3.11/3.12 CI), open PR branch origin/review-fixes (58ec7f2, 2026-11-18: --suite-dir default --seed 1000 alignment and documentation of mean_flow non-uniqueness under pure makespan minimization), and architecture documentation 6b78480 on main.
- **Unique Properties**:
  - Coupled inter-operation perishability constraints (min_wait and max_wait) that expose myopic bottleneck starvation (greedy fails 6/10 medium instances on max_wait, while CP-SAT solves 30/30).
  - Exact half-open interval [start, end) sweep-line capacity checker sorting departures (t, -1) before arrivals (t, +1) for zero-false-positive back-to-back instrument handoffs.
  - Dual lower-bound optimality certification (best_bound and gap_pct) distinguishing proven global optima (15/30 instances at 0.0% gap) from time-bounded feasible solutions.
  - Bit-for-bit reproducible 30-instance JSON benchmark suite paired with an ASCII job-level Gantt timeline visualizer.
- **Deep Profile**: [`labshift/docs/ARCHITECTURE_AND_HISTORY.md`](https://github.com/yaniguan/labshift/blob/main/docs/ARCHITECTURE_AND_HISTORY.md)

## `L4` · [lab-rehearsal](https://github.com/yaniguan/lab-rehearsal)

- **Tagline**: Pre-execution liquid-handling digital-twin rehearsal loop: content-addressed episodic recall, deck simulation, default-deny verification gate, mock dispatch, and JSONL memory write-back.
- **Object**: Prevents unsafe or malformed liquid-handling protocols from reaching physical benchtop robots by running every candidate protocol through a closed five-stage safety loop (recall -> rehearse -> verify -> run -> write_back) between L5 protocol planners/compilers (lab-decide, labshift, stepbot) and L1/L2 hardware executors (lab-hands, Opentrons, PyLabRobot).
- **Data**: Five deterministic JSON liquid-handling protocols in demo/protocols/ (one valid 43-step 8-well 1:2 serial dilution and four targeted failure fixtures: aspirate from empty, out-of-range pipette volume, well overfill, and cross-reagent tip reuse), a 10-run two-pass episodic ledger in demo/memory/runs.jsonl, captured reference stdout (demo/output.txt), and a zero-copy curated catalog of 4 embodied lab benchmarks (LabUtopia, AutoBio, Chemistry3D, Labimus) and 10 open-source robotics/automation simulators.
- **Model**: Zero-dependency deterministic discrete-event deck simulator (96-well plate capped at 300 uL/well, 12-column reservoir capped at 15,000 uL/col, 96-tip rack, 20-300 uL single-channel pipette) paired with a 7-check default-deny rule gate (known_step, volume_in_range, no_overfill, enough_liquid, tip_present, no_tip_reuse, all_tips_dropped). No neural network is trained inside this repository.
- **Training**: Zero parametric training; cross-session adaptation operates strictly via non-parametric episodic memory write-back (append-only JSONL keyed by 12-hex SHA-256 canonical JSON protocol hashes), enabling Pass 2 recall warnings before rehearsal executes.
- **History**: Initial commit 8219695 on main (2026-11-18: 5-stage rehearsal loop demo/rehearse.py, 5 JSON protocol fixtures, 2-pass episodic memory runs.jsonl, demo.yml CI, and curated simulation benchmarks/papers 2017-2026), followed by architecture and ecosystem documentation 5e47a8f on main.
- **Unique Properties**:
  - Five-stage closed safety loop (Recall -> Rehearse -> Verify -> Run -> Write-Back) blocking hardware dispatch unless every step is known and every volumetric/hygiene rule passes.
  - Non-short-circuiting trajectory simulation using bounded physical volume clamping so all cascading step violations are surfaced in a single pass.
